## 2. The changes, in detail

### F-1 — the Rock Account must still answer to the owner {#f-1}

`_requireRockController` was `msg.sender == currentOwner || msg.sender == smartAccount`. The second
clause was justified by a sentence — "the Safe is controlled by the current owner's signing key" —
that is true at awakening and false after every handover, because `claimHandover` changes the owner
and deliberately leaves `smartAccount` alone. For an **open** gift the off-chain Safe owner swap
cannot be pre-signed and never happens at all, so the giver's Safe kept passing the gate for a rock
it no longer owned, and one call to `archiveRock` destroyed the recipient's rock permanently.

The fix asks the account instead of assuming:

```solidity
function _requireRockController(uint256 rockId, Rock storage rock) private view {
    address rockOwner = rock.currentOwner;
    if (msg.sender == rockOwner) return;
    address smartAccount = rock.smartAccount;
    if (msg.sender == smartAccount && _accountAnswersTo(smartAccount, rockOwner)) return;
    revert NotRockOwner(rockId, msg.sender, rockOwner, smartAccount);
}
```

`_accountAnswersTo` calls `isOwner(address)` — Safe's `OwnerManager` view, declared locally as
`ISafeOwnerManager` so the registry carries no Safe dependency — and treats anything other than a
clean `true` as false. Sponsorship still works: a UserOp executed by a Safe whose owner is the
rock's owner passes exactly as before.

**A detail worth recording, because it cost a test run to find.** `try/catch` does *not* catch
Solidity's own "does the target have code" check: that revert is raised in the calling frame,
before the call, so a codeless Rock Account aborted the whole transaction with empty revert data
instead of yielding a readable `NotRockOwner`. `_accountAnswersTo` therefore tests
`account.code.length == 0` first. `testAPlainAddressIsNotAController` pins it.

The alternative fix the audit recommended — bind the claimant's own account during
`claimHandover` — was not taken: it changes the attested claim path and the EIP-712 payload, which
three consumers and a second agent's signer implementation depend on. This fix is confined to one
private function and closes the same hole.

### F-2, F-4 — bounded lifetimes {#f-2} {#f-4}

```solidity
uint256 public constant MAX_ATTESTATION_LIFETIME = 15 minutes;
uint64  public constant MAX_HANDOVER_DURATION    = 90 days;
```

`_consumeAttestation` rejects `deadline > block.timestamp + MAX_ATTESTATION_LIFETIME` with
`AttestationLifetimeTooLong(deadline, maxDeadline)`; `initiateHandover` rejects
`expiresAt > block.timestamp + MAX_HANDOVER_DURATION` with `HandoverTooLong(expiresAt, maxExpiresAt)`.
Both ceilings are inclusive, like every other boundary in the contract, and both have a test at the
boundary as well as past it. The fuzz tests assert the acceptance window is *exactly* the specified
interval over the whole input range, not merely that the two hand-picked points behave.

The values differ from the audit's suggestions (10 minutes, 30 days) on instruction: 15 minutes
gives a real tap-to-bundler round trip headroom, and 90 days covers posting a rock across the world
and forgetting about it.

### F-3 — administration cannot be lost {#f-3}

`Ownable` → `Ownable2Step`, so `transferOwnership` records a pending owner and `owner()` does not
move until `acceptOwnership()`. `renounceOwnership()` is overridden `public pure` and always
reverts `OwnershipCannotBeRenounced()` — for everyone, not just non-owners, so the Etherscan Write
tab shows a button that cannot destroy the contract by mis-click.

### F-5 — mis-sent tokens {#f-5}

The refund block is gone. It read the contract's *whole* balance, so every stray token was paid to
the next person to swap that denomination. The honest path never had a residue — the app consumes
the entire input — so the branch bought nothing and cost a `balanceOf` per swap.

The decision the checklist asks for, made and written into the contract's NatSpec: **tokens sent to
the periphery are lost, and there is no rescue function.** A rescue is an admin key, and this
periphery exists precisely so that no admin key sits on the trade path; a key that can move tokens
out of the contract everybody approves is a larger risk than the occasional mis-sent transfer. The
README repeats it under "two things never to do".

### F-6, F-7 — the callback ticket {#f-6} {#f-7}

Two changes that only work together.

The app is now `XYCSwap public immutable APP`, set in the constructor and dropped from
`swapExactIn`. Nobody can point the periphery at a contract of their own — not through a mistyped
Etherscan field, not through a substituted `NEXT_PUBLIC_AQUA_APP_ADDRESS`.

`swapExactIn` writes a transient *ticket* — token, amount, maker, strategy hash — and
`xycSwapCallback` checks every field against it, clears it before the external calls, and refuses
anything else:

```
UnexpectedCallback          caller is not APP, or there is no swap in progress
UnexpectedCallbackToken     a token this swap never pulled
UnexpectedCallbackAmount    an amount this swap never pulled
UnexpectedCallbackStrategy  a maker or strategy this swap is not settling with
```

Because the ticket is spent, exactly one callback is possible per swap. `swapExactIn` then asserts
the ticket *was* spent (`CallbackNeverHappened`), which additionally proves the app really settled
through us rather than returning with the caller's money still in the contract. A nested
`swapExactIn` is rejected outright (`SwapAlreadyInProgress`), closing F-24's half of the same
concern.

The PoC tests had to be re-expressed, and the new form is stronger. The old ones passed an evil app
to the honest periphery, which is now unreachable — so instead they deploy a periphery *bound to
the evil app*, which is the most authority an attacker can hold once the app is immutable, and
show that even from there the periphery refuses to push a token or an amount its swap never pulled.

### F-8 — the deadline {#f-8}

`swapExactIn` gains `uint256 deadline` as its last parameter and reverts
`SwapExpired(deadline, block.timestamp)` past it. Inclusive at the deadline second, like every
other boundary here. The web encoder defaults it to five minutes from now
(`DEFAULT_SWAP_DEADLINE_SECONDS`), so no caller had to change.

### F-11, F-12, F-14 — deployment and verification {#f-11} {#f-12} {#f-14}

`deploy.js`: `isAddress` is true for the zero address, so a mis-set `ATTESTATION_SIGNER_ADDRESS`
used to deploy a registry in which every awaken and claim reverts — and the read-back check
compared zero with zero and passed. The script now refuses a zero attester before deploying,
asserts the stored attester is both non-zero *and* the intended value afterwards, asserts the owner
too, and warns when the attester equals the deployer key (spec 16 separates those roles).

`deploy-aqua-app.js`: checking for code proved only that *something* is at the address, and the
project has already written the two Aqua-ish Sepolia addresses down the wrong way round on paper.
It now probes the interface — `rawBalances` and `safeBalances`, the two views the integration
actually reads — with all-zero arguments, which a genuine Aqua answers with zeros and a wrong
contract cannot answer at all. It also passes the app address to the taker constructor and reads
`APP()` back.

`verify.md`: the standard-JSON recipe selected `build-info[0]`, which cannot be right for a
two-compiler build. It now selects the build-info whose `input.sources` contains the target file,
prints the compiler version it found, and has a section for `XYCSwap` and `XYCSwapTaker` — including
the fact that `XYCSwapTaker` now takes two constructor arguments.

### F-13 — fuzz tests {#f-13}

Seven, in two new files, all at 256 runs:

`test/BankRockRegistryFuzz.t.sol`
- `testFuzz_counterIsMonotonicAcrossAnySequence(uint32[8], bool[8])` — random counters interleaved
  with retirements; every accepted counter beats every earlier one, only a stale one is ever
  rejected, and retiring releases the tag but never the counter.
- `testFuzz_handoverStateMachineHoldsItsInvariants(uint8[12], uint16[12])` — random action
  sequences over give/claim/cancel/warp/retire; `Archived` is absorbing, a reported
  `HandoverPending` always has a live gift, an expired gift reads `Awake`, a live rock always has
  an owner, and the owner can always act — no sequence strands a rock.
- `testFuzz_attestationDeadlineWindowIsExact(uint256)` and
  `testFuzz_handoverExpiryWindowIsExact(uint64)` — acceptance is exactly the specified interval.

`test/aqua/XYCSwapTakerFuzz.t.sol`
- `testFuzz_theTakerNeverKeepsABalance(uint96, bool)` — the invariant F-5 and F-6 both violated.
- `testFuzz_aStrayBalanceIsNeverPaidOut(uint96, uint96)`.
- `testFuzz_theDeadlineBoundaryIsExact(uint32)`.

### F-16 — errors that say what failed {#f-16}

Every error now carries the values that failed, because Etherscan shows the decoded error and
nothing else. Three were renamed to say *why*, not merely *that*:

| Was | Now |
| --- | --- |
| `InvalidRecipient()` | `RecipientIsAlreadyTheOwner(address recipient)` |
| `InvalidAttester()` | `AttesterCannotBeZero()` |
| `HandoverExpired(uint256, uint64)` | `HandoverExpired(uint256 rockId, uint64 expiresAt, uint64 nowTimestamp)` |

plus parameters added to `InvalidSmartAccount`, `InvalidUidHash`, `InvalidSubject`,
`InvalidHandoverExpiry`, `AttestationExpired`, and a `rockId` added to `NotRockOwner`.
`InvalidRockId()` stays bare: there is exactly one input and its `@notice` says rock id 0 is
reserved.

### F-17, F-18 — Part 2 {#f-17} {#f-18}

Both files re-laid-out to the Part 2.1 order (types → constants → storage → events → errors →
constructor → attested actions → rock-owner actions → administrator actions → views →
internal). Added: `version()` returning `"1.0.0"`, `describeRock(uint256)` returning
`(string state, address owner, address rockAccount, bool lost, uint64 handoverExpiresAt)`,
`@custom:security-contact security@bank-rock.com`, the state-transition table in the contract
NatSpec, enum integers spelled out (`0 = Dormant`, …), a `@notice` on every struct field, storage
variable, event, event parameter, error and function. `solhint`'s `use-natspec` warnings went from
46 to 0.

One gas change came out of the review rather than a finding: `Rock` is reordered so
`currentOwner`, `state` and `lost` share a storage slot — one slot fewer per rock. The struct is
private and `getRock` returns its fields individually, so this is invisible to the ABI.

## 3. Interface changes {#interface}

Three, all in the Aqua periphery, all forced by a finding. The registry's ABI gained functions,
errors and error parameters but **no existing function or event changed name or signature**.

```solidity
// before
constructor(IAqua aqua_)
function swapExactIn(XYCSwap app, XYCSwap.Strategy calldata strategy, bool zeroForOne,
                     uint256 amountIn, uint256 amountOutMin, address to)

// after
constructor(IAqua aqua_, XYCSwap app_)                                              // F-6
function swapExactIn(XYCSwap.Strategy calldata strategy, bool zeroForOne,           // F-6, F-8
                     uint256 amountIn, uint256 amountOutMin, address to, uint256 deadline)
```

Consequences, all handled in this change unless noted:

- `contracts/scripts/deploy-aqua-app.js` passes the app to the taker and reads `APP()` back.
- Every call site in `test/aqua/` and `test/audit/` updated; `BankRockAquaBase` gained a
  `_deadline()` helper.
- The three ABI copies regenerated: `contracts/abi/*.json`, `mcp/registry-abi.ts`,
  `web/src/lib/chain/abi/registry.ts`.
- `web/src/lib/aqua/calls.ts` — `buildSwapCall` encodes the new shape and accepts an optional
  `deadline` / `deadlineSeconds`, defaulting to `DEFAULT_SWAP_DEADLINE_SECONDS` (300), so no caller
  had to change. `SwapPlan` now reports the `deadline` it encoded.

**Two files outside this change's ownership still need a one-time update**, and the web suite has
one failing test until they get it:

1. `web/src/lib/chain/abi/aqua-app.ts` — its `XYC_SWAP_TAKER_ABI` is the pre-audit array. Replace
   it with the contents of `contracts/abi/XYCSwapTaker.json` (regenerated by this change).
   `buildSwapCall` no longer reads it: it encodes against a local fragment, `SWAP_EXACT_IN_ABI`,
   exported from `calls.ts` and marked for deletion once the file is regenerated.
2. `web/src/hooks/useTakerActions.test.ts` — decodes the swap call with that array and asserts
   pre-audit argument positions (`args[0]` the app, `args[5]` the recipient). With the new shape
   the arguments shift down one and `deadline` is `args[5]`. Failing test:
   *"approves the periphery — not Aqua, not the app — and then calls it"*.

## 4. What was deliberately not changed {#not-changed}

**F-19 — the plain-English renames.** The audit recommends `giveRock`, `claimRock`, `cancelGift`,
`retireRock` and matching event names, and Part 2.2 permits the rename. Not done: three consumers
depend on these names — the web chain library, the MCP server's ABI copy, and a second agent's
attestation signer built against `awakenRock`/`claimHandover` — and a rename buys readability that
the fallback the spec itself offers buys just as well. Every `@notice` now opens with the plain
English instead: *"Give this rock away"*, *"Collect a rock that was given to you"*, *"Take back a
gift you opened"*, *"Retire this rock permanently"*. Etherscan shows that sentence directly above
the function. Revisit if the ABI ever breaks for another reason.

**F-21 — no `action` field in the attestation.** Adding `bytes32 action` to the EIP-712 type is
correct and cheap *in the abstract*, and the audit is right that now is when it is cheapest. It is
not done here because the type string is a live contract between this repository and a second
agent's signer, agreed and implemented twice in this session already; changing it a third time
inside a hardening pass that is meant to be reviewable is the wrong trade. The impact today is nil
— `subject` is the same person on both paths — and it becomes real only when a third attested
action exists. **This is the one open recommendation a re-reviewer should weigh**, and it should be
taken before any signer starts producing attestations for a non-claiming purpose.

**F-23 — `getRock` returns a nested struct.** Accepted and documented rather than flattened.
Flattening now would break all three ABI consumers to buy flexibility we have no plan to use; the
NatSpec states that `Handover` is part of the ABI and will not gain fields.

**The eight remaining `solhint` warnings.** All triaged, none actionable:

| Rule | Count | Why not |
| --- | --- | --- |
| `gas-struct-packing` on `Attestation` | 1 | It is an EIP-712 type. Reordering changes the type hash. |
| `gas-small-strings` | 2 | The EIP-712 type string. Unavoidable. |
| `gas-strict-inequalities` | 3 | All three are inclusive boundaries on purpose (F-9). Converting them changes behaviour by one second. |
| `func-visibility` on constructors | 2 | False positive for `>=0.7.0`. |

The `gas-struct-packing` warning on `Rock` is gone — that one was real and is fixed.

**F-10** is web-side and belongs to another agent: a claimable pre-check before broadcasting, a
per-rock rate-limit bucket, refusing when the limiter reports `enforced: false`, and a daily
relayer spend cap. Nothing in `contracts/` can close it.
